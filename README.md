# Сервис генерации и передачи файлов

Сервис на java 21, предназначенный для автоматизированной генерации тестовых банковских данных в виде файлов с фиксированной структурой и их последующей
отправки по различным сетевым протоколам (gRPC Client Streaming, HTTP Multipart, HTTP Chunked).

Система поддерживает внедрение управляемых дефектов в структуру файлов для тестирования.

## Функциональные возможности

* **Генерация файлов фиксированной ширины:** Формирование структуры реестра, состоящей из заголовка (`Header`), тела с данными клиентов (`BankClient`) и последней строкой (`Footer`).
* **Формирование наименований по стандарту:** Генерация имен файлов по маске с использованием юлианской даты и атомарного счетчика.
* **Имитация дефектов:** Автоматическое повреждение структуры файлов: битый заголовок, некоректный подвал, несовпадение количества записей, на основе настраиваемой процентной вероятности.
* **Асинхронное исполнение:** Прием управляющих команд по REST API и обработка задач генерации в фоновых потоках без блокировки ответа.
* **Мультиканальная доставка:** Поддержка трех протоколов сетевой передачи на выбор.
* **Аутентификация и шифрование:** Защита управляющего API с использованием симметричного шифрования AES-128.

## Архитектура системы

Проект реализован без использования ресурсоемких фреймворков и разделен на следующие пакеты:

* `ru.itone.illya4gurenko.config` — Управление конфигурацией (`AppConfig`) и Service Locator (`Base`).
* `ru.itone.illya4gurenko.dto` — Объекты передачи данных JSON-интерфейса.
* `ru.itone.illya4gurenko.handler` — Обработчики HTTP-запросов управляющего сервера.
* `ru.itone.illya4gurenko.security` — Компоненты шифрования (AES) и аутентификации.
* `ru.itone.illya4gurenko.service` — Сервисы генерации данных, файлов и транспортные отправители (`FileSender`).
* `ru.itone.illya4gurenko.struct_file` — Доменная модель структуры банковского реестра.
* `ru.itone.illya4gurenko.grpc` — Протобуф-контракты и сетевые gRPC-компоненты.

## Сборка и запуск

### 1. Компиляция Protocol Buffers и сборка проекта

Для генерации Java-классов из `.proto` контрактов и сборки JAR-архива выполните команду:

```bash
./gradlew clean build
```

### 2. Запуск приложения

```bash
java -jar build/libs/file-generator-service-1.0.0.jar
```

### 3. Переопределение параметров при запуске

Параметры конфигурации могут быть переопределены через системные переменные JVM:

```bash
java -Dfile.out=/opt/app/storage -Dcrypto.key=./config/secret.key -jar build/libs/file-generator-service-1.0.0.jar
```

## Интерфейс управления (REST API)

Запуск процесса генерации осуществляется отправкой HTTP POST запроса.

### Параметры запроса

* **URL:** `http://localhost:8080/api/parametres`
* **Метод:** `POST`
* **Заголовки (Headers):**
    * `Content-Type`: `application/json`
    * `X-Auth-User`: `q1`
    * `X-Auth-Password`: `<Base64_AES_Encrypted_Password>`

### Тело запроса (JSON)

```json
{
  "codeBank": 100,
  "codeFilial": 2,
  "nameAES": "SBER",
  "countRecords": 1000,
  "countFiles": 5,
  "inTime": "2023-12-01T15:00:00"
}
```

### Описание полей JSON

* `codeBank` (integer, обязательное): Код банка.
* `codeFilial` (integer, обязательное): Код филиала.
* `nameAES` (string, обязательное): Наименование автоматизированной системы.
* `countRecords` (integer, обязательное): Количество записей клиентов в одном файле (> 0).
* `countFiles` (integer, обязательное): Количество генерируемых файлов (> 0).
* `inTime` (string, опционально): Плановое время обработки в формате ISO-8601. Если передано null, устанавливается режим немедленного исполнения (`IMMEDIATE`).

### Коды ответов API

* `200 OK`: Запрос успешно валидирован, запущен фоновый процесс генерации.
* `400 Bad Request`: Некорректный JSON или невалидные значения параметров (`countFiles <= 0`).
* `401 Unauthorized`: Отсутствуют аутентификационные заголовки или передан неверный пароль.
* `405 Method Not Allowed`: Использован HTTP-метод, отличный от `POST`.
* `500 Internal Server Error`: Внутренняя ошибка сервера.

## Транспортный слой (Сетевые протоколы)

Сервис поддерживает три изолированные реализации интерфейса `FileSender`:

### 1. gRPC Client Streaming (`StreamGrpcSenderService`)
* **Протокол:** HTTP/2 over gRPC.
* **Формат данных:** Protocol Buffers (`FileChunk`).
* **Механизм:** Потоковая передача файла с диска байтовыми чанками по 64 Килобайта.
* **Особенности:** Минимальная нагрузка на оперативную память, высокая пропускная способность.

### 2. HTTP Multipart (`ApacheMultipartSenderService`)
* **Протокол:** HTTP/1.1 / HTTP/2.
* **Формат данных:** `multipart/form-data`.
* **Библиотека:** Apache HttpClient 5.
* **Особенности:** Потоковая передача тела файла с диска без полной загрузки в память (OOM-safe).

### 3. HTTP Chunked (`ChunkedFileSenderService`)
* **Протокол:** HTTP/1.1.
* **Формат данных:** `text/plain` (Raw Body).
* **Библиотека:** Java 11 `java.net.http.HttpClient`.
* **Особенности:** Передача содержимого файла в виде непрерывного текстового потока.

## Модуль безопасности

1. **Шифрование паролей:** Аутентификация использует передачу зашифрованных паролей в заголовке `X-Auth-Password`. Дешифрование выполняется алгоритмом AES-128 с использованием секретного ключа из файла `secret.key`.
2. **Безопасный режим (Fallback):** Если файл ключа отсутствует по указанному пути, модуль логирует предупреждение и отключает дешифрование, обрабатывая строки в исходном виде.
3. **Белый список (Whitelist):** Валидация пользователей выполняется по локальной таблице соответствия учетных записей.

## Вспомогательные утилиты

В состав исходного кода входят два автономных исполняемых класса для облегчения разработки и тестирования:

### 1. `ru.itone.illya4gurenko.security.CryptoApp`
CLI-утилита для локального шифпрования и дешифрования паролей.

### 2. `ru.itone.illya4gurenko.grpc.TestGrpcServer`
Автономный тестовый gRPC-сервер, поднимающийся на порту `9090`. Используется для локальной проверки правильности отправки байтовых чанков и замера объема полученных данных.
